## 1. 制作プロセス（3ステップ）

大きめの資料・アプリを作るときは、この順番で考えると手戻りが少ない。

1. **要件定義** — 目的を5W1Hで言語化する
   - **Why（最上位の目的）**：これを作る最終的な理由は何か
   - **What / So What（中位の目的）**：目的を達成するために知るべきこと、必要なデータ、それによって行われる判断・行動
   - **Who / When / Where（利用シーン）**：誰が、どんな頻度・タイミングで、どの場所・デバイスで見るか
   - **How（内容）**：必要な機能、データ範囲、更新頻度
2. **プロトタイピング** — 本番の前にラフな画像・ワイヤーフレームで構成を作り、関係者とレイアウトや掲載内容をすり合わせる。ここで合意しておくと、本制作後の手戻り（QCD悪化）を防げる。
3. **制作 → チェック** — 実データを反映し、下記のチェック観点（本ファイル末尾）で最終確認する。

Claudeで資料・アプリを作る際は、いきなり本制作に入らず、簡単でよいので「これは誰が、何を判断するために見るのか」を一言確認してから設計すると、この原則に沿う。

## 2. グラフ・チャートの選び方

| データの性質 | 推奨チャート | 理由 |
|---|---|---|
| 時系列の推移・トレンド | 折れ線グラフ | 連続する時間軸上の変化・傾向を追いやすい |
| ある時点でのカテゴリ比較 | 棒グラフ | 項目間の大小比較に強い |
| 構成比の推移（内訳の変化を時系列で） | 積み上げ棒グラフ | 合計と内訳の両方を時系列で見せられる |
| 構成比そのものを強調したい（合計は重要でない） | 100%積み上げ棒グラフ | 内訳の比率変化に焦点を当てられる |
| ある一時点の構成比（項目数は少なめ、5個程度まで） | 円グラフ・ドーナツグラフ | 全体に占める割合を直感的に把握しやすい。ドーナツは中央にKPI数値を置ける |
| 個別の正確な数値・多項目の一覧比較 | 表 | 正確な値を確認したい、または項目・属性が多い場合に適する |
| 2変数間の相関 | 散布図 | 相関・分布のかたまりを見せられる |
| 地域比較・地理的分布 | 地図（都道府県・市区町村単位など） | 地理的な偏りを直感的に伝えられる |

チャートを選ぶ判断軸は次の2点に集約される。

1. **伝えたいことを確実に伝える**：余計な要素を削ぎ、意味のある順序で並べ、重要な箇所を強調し、見た瞬間に趣旨がわかるようにする。
2. **誤解を生まない表現にする**：軸ラベル・単位を明記し、データの範囲を恣意的に切り取らない、棒グラフ・積み上げグラフの基準線（ゼロ）を省略しない、出典・更新日などのメタ情報を添える。

## 3. Do's / Don'ts（グラフ表現）

### 望ましい表現（Do's）
- 全体を俯瞰できる指標（KPIカード等）と、詳細を示すグラフを併せて配置する
- グラフ内の項目の並び順に意味を持たせる（大小順、時系列順など）
- 本質的でない装飾・過剰なグリッド線は削除する
- 1つのグラフで使う色数は目安として1〜5色程度に絞る
- タイトル・凡例はシンプルに保つ
- 凡例はそれが説明するグラフのすぐ近くに配置する
- 棒グラフ・積み上げグラフの軸の起点は0にする

### 避けたい表現（Don'ts）
- タイトルに、グラフ内にすでにある情報（データ範囲・単位など）を重複して書く
- タイトルや凡例を長文で冗長にする
- グラフと凡例を離して配置する
- 軸の起点を0以外にして、変化を実際より大きく／小さく見せる
- 色だけで系列を判別させる（色覚多様性に配慮できない）
- 3D表現やドロップシャドウなど、データと関係のない装飾的表現を使う

## 4. レイアウトの考え方

- 画面比率は **16:9** を基本とし、**2〜6分割のレイアウトグリッド** に沿って要素を配置する。
- 情報は「左上＝全体像・サマリー」→「右下・下方＝詳細情報」の順に階層的に配置し、利用者が全体→詳細の順で情報にたどり着けるようにする（縦・横どちらの導線でも、全体から詳細へ向かう一貫した流れを保つ）。
- フィルター・操作UIは基本的に画面の上部または左側など固定の位置にまとめ、影響を受けるグラフとの対応関係が視覚的にわかるように近くに配置する。
- 資料・スライド1枚あたりに詰め込みすぎない。情報を減らすか、ページ・タブを分けて段階的に見せる。

## 5. アクセシビリティ

出典：デジタル庁ウェブアクセシビリティ導入ガイドブック
https://www.digital.go.jp/resources/introduction-to-web-accessibility-guidebook
デジタル庁デザインシステム（カラー・コントラスト）
https://design.digital.go.jp/dads/foundations/color/accessibility/

- **背景色とグラフの色のコントラスト比は3:1以上**を確保する。
- 3:1を確保できない場合は、色分け領域の近くに数値を直接記載する、またはマウスオーバー／キーボードフォーカス時に数値を表示する。
- **テキストと背景のコントラスト比は4.5:1以上**を確保する。
- 色だけに頼らず、位置・形・直接ラベルなど色以外の判別手段も併用する（色覚多様性への配慮）。
- グラフには代替テキスト（alt）を付与する。
- 元データをExcel/CSVなどダウンロード可能な形、またはアクセシブルなHTMLテーブルの形でも提供する。

## 6. 最終チェックの観点（要約）

本制作後、以下の観点で見直す。

- **利用者体験**：判断に必要な情報が過不足なく揃っているか。全体像を掴む指標がまず目に入るか。
- **指標・グラフのデザイン**：並び順に意味があるか、グラフと凡例が隣接しているか、軸の起点が0か、色数を絞れているか、不要な装飾がないか。
- **テクニカル**：想定デバイスで問題なく表示・動作するか、表示速度は許容範囲か。
- **データ設計**：目的に合った粒度・更新頻度になっているか、単独では判断が難しい数値に比較対象（目標値・前年値など）が添えられているか。
- **アクセシビリティ**：色のみで判別させていないか、代替テキストがあるか、元データが公開されているか。
